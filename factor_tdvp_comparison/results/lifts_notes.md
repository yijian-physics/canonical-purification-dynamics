# Lift benchmark execution notes

`lift_benchmarks.py` reuses the historical implementations without editing them.

- `half_petz`: original `HalfPetzEvolution`, independently channel-evolved physical factors, active width three, chi-X four for repeated A/B; cap64 for single tilted C.
- `local_unitary` in C: original `compare_tilted_half_petz.local_data_unitary`, active window3 or5, fitting window5 or7 clipped to boundaries, cap64. This reproduces the reported historical single-update numbers.
- `unitary_oracle` in C: original exact-target Procrustes optimum. It receives the global target during construction. Its `oracle_lower_bound` label refers to the theoretical variational optimum on that support, evaluated numerically; it is not a computer-assisted rigorous error bound.
- `local_unitary_regularized` in A/B: a repeated sequential adapter of the unchanged `local_cp_large.fit_gate` and `apply_compact` routines, using independent physical channel caches. Gates are fitted to the local canonical roots, with the original 1e-12 identity regularization and original posttruncation normalization. Three-site active support, five-site training support, cap4, unless explicitly overridden in the resource-control rows.
- `local_unitary_unregularized_adapter`: repeated sequential adapter of the unchanged C local-data fitter, followed by explicit cap4 tensor compression without renormalization. This is a separate stress control, not the original regularized repeated-unitary baseline.

`status=ok` means execution completed, not that an error target was achieved. A/B has a separate `accuracy_status` field for the 1e-3 threshold. Both repeated-unitary adapters fail that threshold on the exactly Clifford cluster inputs at restricted fitting windows, even though non-Clifford inputs are substantially more accurate. Increasing the MPS bond does not fix those cluster failures. An independent audit found the first N=4 boundary update has accurate physical caches and accurate gate application, but the local canonical-root fit sees only a rank-two active row space while the actual global amplitude has rank-four active row space. Its action on the missing directions is unconstrained by the local objective. Full-chain fitting data fixes this first update, while an exact-target unitary on the same active support is also accurate. This is a limitation of the selected practical fitting prescription, not a no-go theorem for local-unitary lifts.

A/B use precisely 20 complete left-to-right sweeps to T=1, with site rates .7+.15*cos(j)^2. The analytic MPS reference is constructed only for scoring after each complete sweep. For N<=6 a separate dense channel calculation validates the reference. C uses p=.1 and T=1, gamma=-log(.8), at the specified tilts.

Timings are split into setup (including physical initial-state preparation and physical-data cache construction), evolution, and scoring. Repeated A/B scoring includes all sweep endpoints. Additional independent dense-reference checks are in `extra_validation_seconds` and excluded from `total_seconds`; they are validation work rather than required scoring. Single C methods are each charged their own state preparation. The oracle's evolution call itself includes a score in the unchanged source routine, so its timing is not a pure production-method comparison. Peak RSS is the process high-water mark, not per-row incremental memory. These runs used one BLAS thread and can share CPU resources with other benchmark workers.

`lifts_history.json` contains standard repeated trajectories; endpoint-only resource controls have rows in `lifts.json`. Every CP score is the raw global amplitude distance to the positive canonical root, with no phase alignment, no purification-gauge optimization, and no normalization adjustment. Dense physical and branch errors are recorded where N<=8; missing dense diagnostics at larger N are null, not zero.
